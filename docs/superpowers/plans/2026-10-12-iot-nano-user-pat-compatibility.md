# IoT Nano User PAT Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Charge Station’s local provisioning, configuration, and runtime integration work with the current Rush IoT Nano public API at ports 17180/17183.

**Architecture:** Charge Station remains an external application. The seed signs in only to bootstrap its isolated tenant and creates its API credential as a normal user’s PAT; the running service uses that PAT exclusively against IoT Nano’s public device, telemetry, and command routes. The existing MQTT simulator continues to authenticate as a device token over the current MQTT listener.

**Tech Stack:** TypeScript, Vitest, Docker Compose, Node.js, Python/Paho MQTT, IoT Nano HTTP API.

## Global Constraints

- Use `IOT_NANO_API_URL=http://127.0.0.1:17180` for host execution and `http://host.docker.internal:17180` from Compose.
- Use MQTT port `17183` for host execution and from the Compose simulator.
- `IOT_NANO_PAT` must be a User PAT whose user owns or manages `IOT_NANO_DEVICE_ID`.
- Never commit generated PATs, device tokens, cookies, or `.charge-station-iot-nano.env`.
